## 攻击点
**NPO 的 unlearning criterion 是 sequence-level likelihood ratio，不是 token-level confidence removal.**

NPO 优化的是：

```text
make log p_theta(y_forget | x) lower than log p_ref(y_forget | x)
```

但自回归序列概率是 token probability 的乘积，也就是 log-prob 的和。于是 NPO 可以通过压低少数几个 token 来让整段 CoT likelihood 大幅下降。这样现有 efficacy metric 会好看，但模型可能仍然在很多关键 content tokens 上保持高 logit margin / 高 max-softmax confidence。


LMF 的意义不是“再加一个不对齐 loss”，而是攻击 NPO 的 blind spot：

```text
NPO: sequence-level suppression
LMF: residual token-level confidence suppression
KL: retain behavior anchoring
```

这要求 LMF 不能再是 blanket flattening。直接 flatten logic 会伤害 reasoning。真正应该做的是：

```text
Residual / gated LMF
```

也就是只在 NPO 已经认为“这个 sequence 被忘掉了”，但 token margin 仍然很高的时候，才施加 LMF。

可以写成：

```text
loss = NPO + KL + μ * gate_NPO_saturated * hinge_LMF
```

其中：

```text
gate_NPO_saturated = stopgrad(sigmoid(beta * (NLL_current - NLL_ref)))
```

解释：

- 当 `NLL_current - NLL_ref` 还小，说明 NPO 还没完成 sequence-level forgetting，主要交给 NPO。
- 当这个差值已经大，NPO 梯度会饱和，认为样本已经 forgotten。
- 但如果此时 forget tokens 的 logit margin 仍高，说明还有 residual token confidence。
- 这时才用 LMF 去 clipping 这个 residual confidence。

LMF 也不要用纯平方：

```text
margin^2
```

而是用 hinge：

```text
max(margin - tau, 0)^2
```

这样不是把所有 logic 压平，而是只惩罚“过度尖锐”的 residual confidence。

这也能解释为什么纯 `LMF+KL` 失败：它没有 NPO 的 directional forgetting signal，只是在压 confidence。  
也能解释为什么 naive `NPO+KL+LMF` 不够强：它没有 gate，会无差别压平。  
真正的破局版本应该是：

```text
NPO + KL + Saturation-Gated Hinge LMF
```

report：**NPO 的缺陷不是忘得不够，而是忘的证据粒度太粗。**



## 分析攻击点理论上真的会发生

需要用 NPO diagnostics 验证比例。

### 梯度饱和是真的

代码里的 NPO 近似是

```python
neg_log_ratios = forget_loss_current - forget_loss_oracle
forget_loss = -F.logsigmoid(beta * neg_log_ratios).mean() * 2 / beta
```

令：

```text
Δ = NLL_current(y|x) - NLL_ref(y|x)
```

NPO loss：

```text
L_NPO = -2/β log σ(βΔ)
```

对 Δ 求导：

```text
dL/dΔ = -2 σ(-βΔ)
```

所以当 Δ 变大，即 current model 已经把 target sequence probability 压得比 reference 低很多时，梯度系数会指数下降。

默认 `β = 0.1`。大概量级：

```text
Δ = 20 nats  -> gradient factor ≈ 0.238
Δ = 40 nats  -> gradient factor ≈ 0.036
Δ = 60 nats  -> gradient factor ≈ 0.005
```

所以“sequence-level suppression 后梯度变小”是 NPO objective 的数学性质。NPO 原论文也强调它比 GA 更受控、collapse 更慢；这正是这个 sigmoid/log-ratio 设计的效果。
### 但它是否会留下 high-margin token？

机制上完全可能，而且概率不低。

原因是：

```text
Δ = sum over tokens [NLL_current_i - NLL_ref_i]
```

这是一个 sequence-level sum。只要若干 token 的 NLL 被拉高，整个 Δ 就可能已经很大，NPO 梯度整体变小。此时别的 token 仍可能保持：

```text
high max-softmax
high logit margin
low entropy
```

NPO 不会单独检查这些局部 token 是否还 confident。它只检查整段 target sequence probability 是否已经被压低。

更进一步，NPO/CE-ascent 类更新甚至可能让模型变成 **confidently wrong**：目标 token 概率下降，但概率质量转移到某个 alternative token，于是 target CoT likelihood 下降了，max-softmax 仍然很高。这种情况下现有 efficacy 可能变好，但“遗忘痕迹”并没有被真正 flatten。

### 是不是高到不可忽略？
理论上满足这几个条件就容易发生：

```text
1. CoT step 有多个 token，Δ 是 token-level NLL change 的总和
2. beta 较小，比如 0.1，需要几十 nats 就进入明显饱和
3. 模型原本对 CoT token 很 confident
4. FF2-only 更新容量有限，更新会集中作用在部分高梯度 token 上
```

任务正好基本满足这些条件。所以：**这是一个合理且不可忽略的理论风险，但还不能只靠纯 LMF diagnostics 证明 NPO 实际发生了这个问题。**

要把它变成 report 里的强论点，需要补一个 NPO diagnostics：

```text
P(problem) = P(NPO saturated AND residual confidence high)
```

具体记录：

```text
npo_gate = 2 * sigmoid(-beta * Δ)
forget_margin_mean
forget_max_softmax_prob_mean
forget_entropy_mean
target_token_prob_mean
```

然后统计：

```text
npo_gate < 0.05
AND forget_max_softmax_prob_mean > 0.5
```

或者：

```text
npo_gate < 0.05
AND forget_margin_mean remains high
```

如果这个比例有 20% 以上，就能说：

> NPO often satisfies sequence-level forgetting while leaving token-level confidence residuals.

这是 LMF 正则的理论落点。


## Diagnostics 设计与当前实验

为了验证这个攻击点，diagnostics 分两层：

### 已完成：sequence-level saturation proxy

脚本：

```powershell
python new_lmf/analyze_npo_saturation_proxy.py
```

输出：

```text
new_lmf/npo_saturation_proxy_summary.csv
```

这个脚本直接读取已有 `final_results/*/*/npo_KL_*.out`。由于 `.out` 没有 logits，它不能证明 token-level residual confidence，但可以用 epoch 0 和后续 epoch 的 `cot_step_prob` 估计：

```text
delta_proxy = log p_epoch0(target) - log p_epoch_t(target)
grad_factor_proxy = 2 * sigmoid(-beta * delta_proxy)
```

注意：`cot_step_prob` 来自 `completion_probabilities`，是 length-penalized log probability，因此这是保守 proxy，不等同于训练时 NPO 使用的 unnormalized sequence NLL gap。

当前结果：

| dataset | model | epoch 5 records | delta_proxy mean | grad_factor_proxy mean | saturated proxy rate |
|---|---:|---:|---:|---:|---:|
| openbook | LLaMA-3-3B | 1308 | 72.027 | 0.034 | 0.907 |
| openbook | Phi-3 | 959 | 0.751 | 0.962 | 0.000 |
| sqa | LLaMA-3-3B | 1228 | 0.600 | 0.970 | 0.000 |
| sqa | Phi-3 | 999 | 27.660 | 0.217 | 0.230 |

解释：

- `openbook/LLaMA-3-3B` 中，NPO 的 sequence-level suppression 很强，到 epoch 5 有约 90.7% step 进入 `grad_factor < 0.05` 的低梯度区。
- `sqa/Phi-3` 中，这个现象较弱但不可忽略，约 23.0% step 进入低梯度区。
- `openbook/Phi-3` 和 `sqa/LLaMA-3-3B` 中，按这个 proxy 看几乎没有 saturation；这说明理论问题不是所有组合都显著存在，extension 的收益也可能是 dataset/model dependent 的。

这个实验支持“sequence-level NPO saturation 在部分主实验组合中真实且高频发生”，但没有证明“saturation 后仍有 high-margin tokens”。

### 已编写但需 GPU 环境运行：true residual-confidence diagnostics

脚本：

```powershell
python new_lmf/run_npo_residual_diagnostics.py --short_model Phi-3 --dataset openbook --lr 1e-4 --n_unlearn 5 --epochs 5 --trust_remote_code
```

这个脚本会重新跑小规模 `NPO+KL`，直接从 logits 记录：

```text
npo_delta
npo_grad_factor = 2 * sigmoid(-beta * delta)
forget_margin_mean / max
forget_max_softmax_prob_mean / max
forget_entropy_mean
target_token_prob_mean
positive_delta_top1_share
positive_delta_top20pct_share
saturated_and_high_conf
retain_kl
```

它检验：

```text
P(NPO saturated AND residual confidence high)
```

也就是：

```text
npo_grad_factor < 0.05
AND forget_max_softmax_prob_mean > 0.5
```

如果这个比例在某些组合中明显大于 0，例如超过 20%，就可以更强地写：

> NPO often satisfies the sequence-level forgetting criterion while leaving token-level confidence residuals.
